# blake3

This is a performance-focused fork of `lukechampine.com/blake3` v1.4.1. It
retains the upstream portable implementation and public API, reworks the
upstream AVX2 and AVX-512 kernels, and adds an ARM64 four-chunk NEON backend,
bounded tree-hash scheduling, and zero-allocation keyed one-shot helpers.

```sh
go get github.com/jmwoliver/blake3
```

`blake3` implements the [BLAKE3 cryptographic hash function](https://github.com/BLAKE3-team/BLAKE3).
This implementation aims to be performant without sacrificing (too much)
readability, in the hopes of eventually landing in `x/crypto`.

Architecture dispatch is internal to the module:

- AMD64 uses AVX-512 (sixteen or eight inputs per call) or AVX2 (eight inputs
  per call) for chunks, Merkle parents and extended output, and a
  single-block kernel for short messages and for whatever does not fill a
  batch. AVX-512 requires AVX512F and AVX512VL. The assembly is generated by
  `avo/gen.go`; run `go generate ./guts` after changing it.
- ARM64 uses four-lane NEON for groups of independent full chunks and the
  portable single-node compressor for small messages and Merkle parents.
- Other architectures use portable Go.

`NewSerial` provides the same streaming API without internal worker
goroutines for applications that already batch independent messages.

The ARM64 kernels were ported from `goforge.dev/blake3sum` v1.0.0. See
`THIRD_PARTY_NOTICES.md`, `LICENSE`, and `LICENSE-GOFORGE` for provenance and
license terms.

## Shortcomings

ARM64 has no assembly routine for single-block compressions. This is most
noticeable for ~1KB inputs.

A streaming `Hasher` compresses the last chunk of every `Write` on its own,
because it cannot know whether more input follows. Callers that have the
whole message should prefer `Sum256`, `Sum512` or `Sum256Keyed`, which hash
the final chunks in the same batch as their neighbours.

Each AMD64 assembly routine inlines all 7 rounds, causing thousands of lines
of duplicated code. Ideally the routines could be merged such that only a
single routine is generated for AVX-512 and AVX2, without sacrificing too much
performance.
